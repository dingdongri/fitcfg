# 학교 GPU 서버(gfarm) 실측 리포트 — A100 80GB의 MIG 3g.40gb 1조각

- 기간: 2026-10-20 ~ 10-21 · 환경: 드라이버 535, torch 2.6.0+cu124, transformers 5.20.2, peft 0.21.2, bitsandbytes 0.50.2
- 슬라이스: 메모리 39.25 GiB, bf16 행렬곱 110 TFLOPS (이론 3/7 × 312 = 133.7의 82%), FlashAttention 동작
- 측정량: 단일 GPU 학습 157개(성공 141 · OOM 16) + 단편화 시험 18개 + 병렬 설정 rank 0 실측 72개(성공 64 · OOM 8)
- 재현: `scripts/setup_gfarm.sh` → `scripts/run_all_mig.sh` → `run_next_mig.sh` → `run_fix_mig.sh`

### 1-2. 가중치 항은 정확, 오차는 활성값 항에서

- 8B 모델 로드 직후 메모리 예측 오차 ±0.3% (QLoRA 4bit 포함) → 남은 오차는 토큰 수에 비례하는 활성값 항
- 같은 토큰 수면 같은 메모리 (batch 1×2048 = batch 2×1024, 0.01GB 이내) → 토큰 수 기반 식 구조 확인

### 1-3. 발견: 어휘(vocab) 크기가 다른 모델이 보정에 필요

- 기존 보정 모델(Llama·Qwen)은 어휘가 모두 128K~152K → '어휘에 비례하는 메모리(logits)'와 '층에 비례하는 메모리'가 통계적으로 구분되지 않음
- Mistral(어휘 32K)을 보정에 넣자 처음 보는 Phi-3(어휘 32K) QLoRA 오차 **13.6% → 4.8%**
- → Mistral-7B-v0.3을 지원 모델(MODELS)에 추가, Phi-3·Gemma는 일반화 시험용으로 보정에서 제외

## 3. QLoRA 메모리 단편화 → `expandable_segments`

- QLoRA는 할당기 단편화(예약 − 실제 사용)가 큼: 체크포인팅 시 평균 1.7GB, 최대 2.8GB (LoRA 0.4GB, T4 0.7GB)
- `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`로 같은 18개 재측정:

| | 단편화 (예약−사용) | GPU peak 감소 | 속도 |
|---|---|---|---|
| QLoRA (14개) | 평균 1.6 → 0.6GB | 0.15 ~ **1.76GB** (최대 8%) | 변화 없음 (1.00×) |
| LoRA (4개) | 0.4 → 0.2GB | 0.12 ~ 0.42GB | 변화 없음 |

- 실제 사용량(allocated)은 0.01GB 이내로 같음 → 예측 식은 그대로, 생성 스크립트(`train.py`)에 이 설정을 기본으로 넣음 → 실제 peak가 예측보다 더 낮아져 OOM 여유가 늘어남

## 5. GPU 여러 장 설정의 'GPU 1장 몫' 실측 (가짜 분산 통신 + 실제 GPU)

- 방법: 분산 통신을 아무 일도 하지 않는 가짜 그룹으로 바꾸고 rank 0만 실제 GPU에서 실행 → 실제 CUDA 할당기 기준 메모리 + 통신을 뺀 계산 시간
- MIG 조각은 서로 통신할 수 없어 진짜 멀티 GPU는 아님 → **통신 시간은 여전히 가정**

### 5-1. 메모리: CPU 가짜 텐서 추적 vs 실제 GPU

**요약**: 64/72 성공 (OOM 8개는 GPU 2~4장으로 8B Full을 나눈 경우 — sim 식도 8개 모두 OOM으로 예측, 성공 64개 중 OOM 예측 0 → **OOM 판정 72/72**)

| 종류 · 방식 | n | CPU 가짜 텐서 추적 오차 | sim_3d 식 오차 |
|---|---|---|---|
| FSDP Full (1B·8B, GPU 2·4·8장, root/split) | 13 | **1.5%** (−0.5 ~ +4.3%) | 2.8% (+0.9 ~ +5.9%) |
| FSDP LoRA | 20 | **2.8%** (+0.1 ~ +6.9%) | 12.9% (+4.3 ~ +25.5%, 전부 과대) |
| PP Full (8B 4단계, first/mid/last) | 12 | **0.1%** | 2.6% (−4.2 ~ +4.3%) |
| PP LoRA | 12 | 4.5% (+0.4 ~ +11.5%) | 9.0% (−3.2 ~ +18.1%) |
| TP Full (1B·8B, 2·4장) | 7 | **0.8%** | 1.1% (−2.8 ~ 0%) |

- CPU 추적기 = 실제 GPU와 평균 2.1% (n=61) → **GPU 없이 병렬 설정 메모리를 재는 방법이 실측으로 검증됨**
- sim 식: Full은 3% 안쪽, LoRA는 과대예측(안전한 쪽이지만 FSDP+LoRA를 실제보다 덜 공격적으로 추천) → LoRA 활성값 항 후속 보정
- 측정 중 발견한 함정 2개 (측정 코드 문제, 실제 학습과 무관): FSDP2는 한 단위 안의 정밀도가 같아야 함(LoRA 어댑터 fp32 → bf16으로 맞춤), meta 장치로 만든 모델은 임베딩·lm_head 공유가 풀림(TP 1B가 2GB 더 잡힘 → 다시 묶고 재측정, 오차 −18% → ±2%)
- 전체 표: `reports/gpu_parallel_report.md`

### 5-2. 계산 시간: sim_3d 식 vs 실측

- 기존 sim_3d 계산 항(단일 GPU 효율 적용)은 실제보다 **1.2~3.2배 느리게** 잡혀 있었음 (중앙값 FSDP 1.33×, PP 1.94×, TP 2.45×)
- 실측 64개로 다시 맞춤: 효율 full 0.74 · lora 0.68 (qlora 0.55 = 단일 GPU 비율), util 절반점 512토큰 → 평균 오차 11.5% (`scripts/fit_sim_compute.py`)
- PP 마지막 stage(lm_head+loss)는 같은 층 수의 다른 stage보다 20~23% 느림 → 층 나누기에서 마지막 stage에 층을 덜 주는 근거
- 고친 계산 상수로 3D 시뮬레이션 재실행 (`python scripts/sim_3d.py --measured` → `reports/sim_3d_report_recal.md`):

| 하드웨어 | 기존 이득 (낙관 / 비관) | 재보정 이득 (낙관 / 비관) |
|---|---|---|
| A100 NVLink, 8B | 1.00~1.06 / 1.00~1.06 | **1.00 / 1.00** (FSDP가 최적 유지) |
| A100-80 ×8, 70B LoRA·QLoRA | 1.04~1.12 / 1.00~1.09 | 1.19~1.20 / 1.15~1.21 |
| 4090 PCIe, 8B | 1.00 / 1.07~1.30 | 1.00~1.17 / 1.16~**1.80** |
| 3090+4090 혼합, 8B | 1.55~1.65 / 1.79~2.03 | 1.49~1.55 / 1.97~2.17 |

- 해석: 계산이 생각보다 빠르면 통신 비중이 커짐 → **NVLink에선 결론 그대로(FSDP), PCIe·큰 모델에선 3D(특히 PP) 이득이 커짐**, 혼합 GPU는 그대로 1.5~2.2×
- 단, A100에서 잰 효율을 4090·3090에 그대로 쓴 것은 가정
